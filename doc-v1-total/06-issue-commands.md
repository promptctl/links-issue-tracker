# CLI: issue commands

`lit` is a single binary whose subcommands cover the issue workflow: create, list, show, update, rank, transition, purge, record a plan review, relate, comment, label, bulk-edit, and import/export. This chapter specifies every issue-facing command — its flags, refusal conditions, exit codes, side effects, and exact output — plus the shared CLI plumbing they all run through: argument dispatch, error conventions, identity resolution, and the workability predicate behind `backlog` and `next`. Operations commands (`init`, `sync`, `doctor`, backups, etc.) are chapter 07; claims internals are chapter 08; workflow guidance dispatch is chapter 09.

Two global facts shape everything below. First, output is line-oriented text: exactly one command in this scope emits JSON (`lit export`), and the removed `--output` flag is actively rejected everywhere (`internal/cli/cli.go`). Second, issue IDs are always passed verbatim — there is no fuzzy or short-prefix ID resolution anywhere in the CLI; a wrong ID is a not-found error, exit 4 (`cli.go`).

## Command dispatch and flag parsing

The whole command tree is a table of `CommandSpec` rows (`register.go`). Every cobra command is created with flag parsing disabled (`DisableFlagParsing: true`), so each handler parses its own argv slice (`register.go`). Consequences a reimplementer must preserve:

- **Global argument scan** (`cli.go`): covers the root's flag region, the flag-shaped tokens before the first positional; a `--` there is consumed and ends the scan; a `--output` (or `--output=x`) there is rejected before any command runs with "`--output` is no longer supported; omit it for text output" → exit 3.
- **Bare `lit`**: outside a git repo prints cobra help; inside a workspace prints the quickstart guidance, byte-identical to `lit quickstart` (`cli.go`). `lit <unknown-token>` → `unknown command "<x>"` → exit 3, the same with a `-h`/`--help` on either side of the token (`cli.go`).
- **Per-command flag parsing** (`parseFlagSet`, `flagset.go`): `--help` prints `Usage of <cmd>:` plus flag defaults **to stdout** and exits 0. An unknown `--output` or `--continue` maps to a tailored retirement message (exit 3); any other unknown flag is a usage error, exit 2. Flag kinds include repeatable string-array flags (never comma-split) and "string-optional" flags that take one value when present bare (`cli.go`). Flags can be registered hidden-but-functional (`cli.go`).
- **Positional/flag splitting** (`splitArgs`, `flagset.go`): a `-`-prefixed token goes to the flag slice and consumes the following token as its value only when the flag set says that flag takes one — the predicate is `takesValue` (`flagset.go`), read through `flagTakesValue` (`flagset.go`), and it mirrors pflag's own rule: a flag whose `NoOptDefVal` is empty consumes the next token whatever that token looks like. A POSIX `--` terminator is honoured — every token after it is a positional whatever it looks like, up to the declared ceiling, and tokens past the ceiling stay in the flag stream. Extra non-flag tokens beyond the ceiling are refused in one place, `refuseSurplusPositionals` (`register.go`), called from `parseLeaf` (`register.go`) before the workspace is acquired, so `lit new … stray`, `lit export stray`, `lit followup … stray`, `lit rank <id> extra` and `lit parent clear <id> extra` are all usage errors → exit 2. The refusal sentence is the leaf's own (`leaf.usage`) when it sets one, otherwise derived from the flag set by `derivedUsage` (`register.go`), which names the flags the command takes a value for, or points at `--help` when there are more than four. `ls` and `children` declare the arity they have and read the positionals they are given rather than pflag's leftover arguments; `listPositionals` (`cli.go`) reads the declared channel only.
- **Family dispatch** (`register.go`): multi-word commands (`comment add`, `dep ls`, …) resolve `args[0]` by exact string match against a family table. Zero args or an unknown subcommand return the usage string as a **plain error → exit 1**, whereas per-command usage refusals are `UsageError` → exit 2. The transition commands' wrong-arity refusal and `completion`'s are `UsageError` → exit 2.
- **Store access**: handlers are wrapped with a fixed access mode (read/write). Opening outside a git repository yields "links requires running inside a git repository/worktree" → exit 3 (`cli.go`). After a successful **write** command, the wrapper prints the mutation sync-staleness warning and then runs post-command auto-sync (`cli.go`).

Help groups, in order: Human Bootstrap, Agent Operations, Dependencies & Structure, Sync & Data, Setup & Maintenance, Issue Retention, Guidance & Tooling (`register.go`).

## Exit codes and error output

Eight constants, 0 through 7 (`exit.go`), mapped from error type by `ExitCode` in a fixed dispatch order (`exit.go`). Exit 6 is `ExitNoWork` — "ran correctly and changed nothing" — and it is reached by three arms, not just the router's two: a caller looping `lit next` has to tell "stop, there is nothing for you" from "lit is broken", and under `ExitGeneric` its only way to do that was to parse the English.

This table is the corpus's single source for the code-to-error-type mapping; `07-ops-commands-and-sync-engine.md`, `09-workflows.md` and `10-platform.md` point here rather than restating it.

| Exit | Constant | Error types |
|---|---|---|
| 0 | `ExitOK` | nil error, including a handled `--help` |
| 1 | `ExitGeneric` | `BulkFailureError`, transient GC contention, everything else |
| 2 | `ExitUsage` | `UsageError` |
| 3 | `ExitValidation` | `UnknownCommandError`, `RetiredCommandError`, any `model.Refusal` (`model.ValidationError`, `model.FrozenIssueError`, and the upgrade/downgrade target refusals), `UnsupportedError`, `templateShapeError`, `OutsideWorkspaceError`, `store.ErrWorkspaceNotInitialized`, any `model.SchemaAhead` (`*store.UnsupportedSchemaVersionError`, `*store.DowngradeSpanUnsupportedError`, `*store.RemoteSchemaAheadError`, which a remote-schema-ahead `SyncFailureError` unwraps to), `*store.QuarantineBlockError`, `workspace.ErrIssuePrefixRefused`, any `model.StateRequestError` (`model.ContainerActionError`, `lifecycle.RetentionError`) when not `Satisfied()`, `takeoverUnconfirmedError`, `purgeUnconfirmedError` |
| 4 | `ExitNotFound` | `storage.NotFoundError`, `storage.VersionNotFoundError` |
| 5 | `ExitConflict` | `MergeConflictError`, `SyncFailureError` (except one that unwraps to a `model.SchemaAhead`), owner-approval refusal |
| 6 | `ExitNoWork` | `Exhausted`, `NoWork`, any `model.StateRequestError` when `Satisfied()` |
| 7 | `ExitCorruption` | `CorruptionError` |

On failure the process prints to stderr: `error (code=N, reason=<reason>): <message>`, then a `remediation:` line when the reason has one (`error_output.go`). The reason is how a script tells apart failures that share an exit code. Each error type maps to a reason string (`entity_not_found`, `usage_error`, `corruption_detected`, …) and each reason to a fixed remediation sentence — e.g. not-found → "Verify the target ID exists with `lit ls` or `lit show <id>`."; corruption → "Run `lit doctor --fix integrity` and retry." Several remediations embed literal `<agent-instructions>` tags that tell agent callers whether the fix needs the user: `corruption_detected` and `transient_gc_contention` call it idempotent and safe to run without confirmation, `workspace_write_blocked` calls the state resolvable without the user's input, and `takeover_unconfirmed`, `purge_unconfirmed`, `workspace_schema_ahead`, and `migration_quarantined` say to act only when the user directs it (`error_output.go`). Progress/diagnostic text goes to stderr as `lit: <operation>: <text>`; stdout is the result channel (`progress.go`).

## Identity, breadcrumbs, banners, events

**Actor/assignee identity.** If env `CLAUDE_CODE_SESSION_ID` is set, the identity is `claude_<session-id>`, overriding any explicit value; otherwise the trimmed explicit value (`cli.go`). Most mutating commands, and `next`, register a `--by` flag as the explicit fallback, listed in help with the one usage string `byUsage` (`cli.go`). An empty actor is stored as `unknown` (`internal/store/store.go`). The rules deliberately diverge by command: `start` assigns the `--by` identity through session-identity resolution (env wins), while `update --assignee`, `new --assignee`, and `followup --assignee` write the trimmed literal — so `update --assignee ""` clears the assignee (`cli.go`). Every one of them, `start` included, refuses an assignee that carries a comma with a `model.ValidationError`, exit 3, since every assignee filter splits on commas (`internal/model/assignee.go`). An empty assignee renders as `(unassigned)`.

**Breadcrumbs.** Successful mutations append `deeper guidance: lit quickstart <topic>`: `new`/`followup` → topic `new`; `update`, `rank`, `rank set`, `dep add/rm`, `label add/rm`, `parent set/clear` → `update`; `start` → `work`; `done`/`close` → `done`. The other transitions, `purge`, `verdict`, and `comment` emit none (`quickstart_topics.go`, `cli.go`, `purge.go`). Emitting an unregistered topic panics.

**Sync-staleness banners.** Read commands `backlog`, `next`, and `show` (full-detail mode only — suppressed under `--field` to keep output machine-parseable) print a staleness warning before their payload; write commands get one after success (`cli.go`).

**Workflow events.** Commands dispatch occasions rendered by the workflows subsystem (chapter 09): `show` → show-ticket, `backlog` → show-backlog, `next` → next-pulled, `new`/`followup` → ticket-created, `update` → ticket-updated, `comment add` → comment-added, and the status transitions map `start`→work-started, `done`→work-finished, `close`→ticket-closed, `open`→ticket-reopened (`workflow_events.go`). Retention actions (archive/unarchive/delete/restore) fire no event (`cli.go`), and neither do `purge` (`purge.go`) and `verdict` (`verdict.go`). Bulk operations fire no events at all.

## Output primitives

- One-line success form (used by `new`, `followup`, `update`, `rank`, transitions): `id [state/type/topic/priority] title[labels]` (`output.go`). State renders as the status, then `:<resolution>` when the close recorded one (`duplicate`, `superseded`, `obsolete`, `wontfix`; a `done` close records none), then a `+archived` or `+deleted` suffix when frozen — never both — so `closed:wontfix+archived` is one cell (`output.go`). The list `state` column renders the same cell (`columns.go`).
- List rendering: default column set `id, state, topic, title`; valid names are `assignee, blocked, created_at, id, labels, parent, priority, rank, state, title, topic, type, updated_at` (`columns.go`). A `--columns` value is lowercased and split on commas; an empty selection gives the default set, and an unknown name is a usage error, `unknown --columns name "<x>"; valid columns: …`, exit 2 (`columns.go`). `lit ls`'s `lines` format joins with `" | "`; `table` writes an uppercased tab-aligned header + rows (`output.go`). In `lit ls`, naming `parent` batch-loads relations, and naming `blocked` runs the annotation pipeline `lit next` and `lit backlog` use; `blocked` shows the literal `blocked` when the readiness verdict is not ready, else `-` (`cli.go`, `workable.go`).
- Timestamps: RFC3339 in columns and `--field`; history timestamps render `Jan 2, 2006 3:04 PM MST` in local time (`output.go`). Durations humanize to coarse buckets: days ≥48h, hours ≥2h, minutes ≥2m, else "under a minute" (`output.go`).
- Vocabulary parsing at the CLI boundary: issue types and priorities on write paths wrap failures as validation errors (exit 3); the read-path `--type`/`--status` filters return bare parse errors. CSV inputs split on `,`, trim, and drop empties (`cli.go`).

## The workability predicate

`backlog` and `next` share one pipeline (`cli.go`; annotators in `ready_state.go`):

1. **Candidate set**: list issues with statuses `[open, in_progress]` (or the single `--status` value), plus any type/assignee/labels filters; archived and deleted excluded; store order is rank-ascending.
2. **Leaves only**: containers (epics) and closed issues are dropped — an epic is never a workable row (`cli.go`).
3. **Annotators**, each attaching typed annotations:
   - *Required fields* — from config `ready.required_fields`; a policy naming a non-wire field is a validation error. A field is "set" if non-nil, non-blank (strings), non-empty (arrays/maps). Each unset field → `MissingField`.
   - *Blockers* — each non-closed dependency → `OpenDependency`; additionally `RankInversion` when tree order lists the dependency after its dependent — the two compared through the epics that hold them, never by their own keys across frames, and neither an edge between an issue and its own container nor one between interleaved epics counted (`storage.DependencyOrder.Inverted`, read once per pass). Each non-closed dependency of any epic above the issue, climbing through nested epics and stopping at a parent that is not an epic, that the issue does not already depend on directly → `InheritedDependency` (no rank inversion), unless that dependency already waits on the issue: through its own dependencies, blockers inherited from epics above it, an epic waiting on its children, and earlier lane-mates, the issue itself included. Honoring such an edge would leave the two waiting on each other forever. A blocker inherited through a link that is itself dropped carries no wait further, and two links that could each hold only while the other does not both drop. The ancestor epics are loaded one batched query per nesting level, and the wait graph from every such dependency one query per step (`ready_state.go`).
   - *Sibling gate* — when the parent is an epic: each sibling with the same lane and a lower rank that is still in play → `EarlierSiblingPending`. The sibling set is the epic's **unfiltered** in-play children, so siblings hidden by CLI filters still gate (`ready_state.go`).
   - *Orphaned* — `in_progress` issues untouched for ≥ 6 hours (constant, `ready_state.go`).
   - *Reserved blocking labels* — the label `needs-design` → `NeedsDesign`; the label `external` → `External`. The message is the label (`ready_state.go`).
   - *Focus path* — issues on the prerequisite closure of any open goal labeled `focus`, computed by BFS over dependencies, dependencies inherited from ancestor epics, container children, and earlier same-lane siblings; shared prerequisites attribute to the first goal reached (`ready_state.go`).
4. **Classification**: annotations map to roles — blocking (`MissingField`, `OpenDependency`, `InheritedDependency`, `EarlierSiblingPending`, `NeedsDesign`, `External`), orphaned, rank-inversion, or none (`FocusPath`). **Ready = zero blocking annotations** (`readiness.go`). An unclassified kind panics.
5. **Ordering**: the listing's rank order — tree order, so a leaf inside an epic sorts at the epic's place, then by its own rank — then one stable sort by priority (urgent first). Focus is a scope over the rows, not a sort key (`cli.go`, `ready_state.go`).

Rollups partition rows as: `in_progress` first (even if also blocked), else blocked, else ready (`ready_state.go`).

## Creating issues

**`lit new`** (write; `cli.go`). Flags: `--title`, `--description`, `--prompt` (reusable agent prompt), `--plan` (how the work will be done, for a law review before it starts; each edit is a new version, and `lit verdict` records a review of one), `--description-file`, `--prompt-file`, `--plan-file`, `--type` (default `task`), `--topic` (required immutable slug), `--parent` (the epic the ticket lives inside, required for every type but `epic`; child IDs become `parentID.<hash>`), `--priority` (`normal`|`urgent`, or the equivalent `0`|`1`; default `normal`), `--assignee` (trimmed literal; a comma refused, exit 3), `--labels` (CSV), `--lane` (partitions an epic's children into parallel rank-ordered sub-sequences), `--top` (rank at top; default appends to the bottom of its frame). Type/priority validation → exit 3. Store refusals: blank title ("title is required"), missing/short/long topic, a leaf with no `--parent` ("cannot create a task outside an epic: every ticket except an epic lives inside one, so give it the epic it belongs to as its parent, or make it an epic"), and a `--parent` that is not an epic ("cannot file a ticket under X: it is a task, and only an epic contains tickets") → exit 3; nonexistent parent → exit 4. Labels are canonicalized, de-duplicated, sorted. Output: the summary line + breadcrumb. Note `newLeaf` registers no `--by`; creation attribution is not CLI-settable here.

**`lit followup`** (write; `cli.go`). Files a follow-up beside a just-closed ticket: the new issue's parent is the `--on` ticket's own parent (none when it has none — a top-level epic, so a leaf-typed follow-up of one is refused by the store's containment rule, and `--type epic` lands beside it at the top level), read through `GetIssueDetail`, unless `--parent` names the epic to file it in instead, and its `follows_up` is the `--on` ticket's id. Flags: `--on` (required id of the ticket it follows up), `--title` (required), `--description`, `--prompt`, `--description-file`, `--prompt-file`, `--type`, `--parent` (the epic to file it in; blank keeps it beside `--on`), `--topic`, `--priority`, `--assignee`, `--labels`, `--top` — no `--lane`. Blank `--on` or `--title` → usage error, exit 2; a missing `--on` ticket → exit 4. Defaults inherited from the `--on` ticket: blank topic takes its topic; blank description becomes "Follow-up surfaced at the close of `<id>`: `<title>`". `lit show` renders the link on both ends as the `follows_up:` and `follow_ups:` groups, after `related:`.

## Querying

**`lit ls`** (`cli.go`). Lists issues, rank order by default. Uniquely, it is not bound to the current workspace: `--at <store-dir>` opens any discovered store read-only (blank or `-`-prefixed value → usage error). Filter flags: `--status` (a set: comma-separated and/or repeated, ORed), `--type` (a set: comma-separated and/or repeated, ORed; every member validated), `--assignee` (comma-separated and/or repeated, ORed), `--search` (repeated, never comma-split; each occurrence is one term and every term must match), `--ids` (issue ids, comma-separated and/or repeated), `--parent` (issue ids, comma-separated and/or repeated; selects their direct children, ORed), `--labels` (comma-separated and/or repeated, ALL must match) — a bad member of any of these six sets, including a blank slot such as `--parent=` or `--ids a,`, or a blank `--search`, → validation error, exit 3, `--has-comments` (tri-state: only applied when the flag is present, so `--has-comments=false` selects issues *without* comments), `--include-archived`, `--include-deleted`, `--updated-after`/`--updated-before` (RFC3339; a value that is not, or an after later than the before, exit 3), `--sort` (`field[:asc|desc]` CSV), `--columns` (unknown name exit 2), `--format` (`lines`|`table`; anything else exit 3), `--limit` (negative exit 3), and `--query`.

The `--query` language (`internal/query/query.go`) tokenizes with single/double quotes and accepts: `status:<state>[,<state>...]`, `resolution:<res>`, `type:<type>[,<type>...]`, `assignee:<v>[,<v>...]`, `id:<v>[,<v>...]`, `parent:<v>[,<v>...]`, `label:<v>[,<v>...]` (a blank slot, such as a bare `parent:`, is an error), `has:comments`, `sort:<spec>`, `limit:<n>` (non-negative integer), bare `archived`, bare `deleted`, `updated` followed by `>=`, `>`, `<=` or `<` and an RFC3339 timestamp, and free text as search terms. Query and flag filters merge: slices dedupe or append, archived/deleted OR, a positive query limit overwrites; conflicting has-comments or time bounds, and after > before, are errors (`query.go`).

Default active-work filter: if after merging no statuses **and no resolutions** are set, statuses default to `[open, in_progress]` — so a resolution filter alone reaches closed issues (`cli.go`).

**`lit show <id> [--field ...]`** (`cli.go`). Wrong arity → usage error, exit 2. `--field` mode prints selected fields with no context: valid names `id, title, description, prompt, plan, type, topic, priority, status, phase, assignee, labels, rank, lane, follows_up, created_at, updated_at`; one field prints the bare value, several print `name: value` lines in requested order; an unknown name errors before anything prints. Full-detail mode prints, in order: header (id, title, type, topic, priority, labels, archived, deleted); status+assignee(+resolution) for leaves or child progress counts for containers; `unblocks:` (live dependents); a parent block with its description; description; prompt; the plan section (below); then group blocks `children`, `blocked_by`, `blocks`, `redirect` (the close-redirect target), `related`, `follows_up` (the ticket this one follows up), `follow_ups` (the tickets filed as follow-ups of this one), each omitted when empty — there is deliberately no siblings group; comments (`- <comment-id> [author] body`, the id `lit comment rm` takes, each later line of the body indented two spaces); **no history** (that is `lit history`); and finally the epic-context block (`output.go`). The epic-context block is resolved before the full-detail output above is written (`cli.go`), so the body and the block are all-or-nothing: a failure to build the block — including an unreadable `.lit/config.toml` — exits nonzero with neither printed. The sync-staleness banner and any fired show-ticket workflow body precede that resolution and are written either way.

The **epic-context block** (`epic_context.go`): a container shows its own children's plan; a leaf inside an epic shows the parent's plan with itself marked `▶ … (you are here)`; other issues get nothing. Shape: `Epic: <id> — <title>`, `Why: <first non-blank description line>`, then per-child lines with a status marker — `[archived]` / `[deleted]` for a child off the flow, else `[in_progress]`, `[closed]` (or `[closed:<resolution>]` when the close recorded one: `duplicate`, `superseded`, `obsolete`, `wontfix`), `[blocked: <reason>[; <reason>…]]`, or `[ready]` — plus `[lane: <key>]` when set, and a `Cross-epic dependencies:` block listing `Blocks outside the epic` / `Blocked from outside the epic` edges for open dependencies crossing the epic boundary. A child's ready/blocked marker is the annotation-registry readiness verdict — the same one `lit next` routes on and `lit backlog` renders, over the same annotator set — so each blocking reason reads as `by <id>`, `earlier sibling <id> still open`, `missing <field>`, `needs-design`, or `external`, and a child no surface would serve cannot render `[ready]`. The `ready.required_fields` policy backing the `missing <field>` reason is read from repo config (`config.Load`) only when the shown issue has a plan slice (`epic_context.go`); an issue in no epic reads no repo config, so a config that fails validation for an unrelated reason does not affect `lit show` on it.

**`lit history <id>`** (`cli.go`). Prints id, title, then `history:` and per event `- [<actor> @ <local timestamp>] <action> <reason>` (an action-less event displays `update`), then per field change `    <field>: <from> → <to>` with `-` for empty sides. A change to a long text field (`description`, `prompt`, `plan` — the rows of `storage`'s field table that declare `LongText`, `fields.go`) prints `    <field>: v<n> → v<m>` instead, with no text, and `-` for an empty side. The numbers come from `storage.TextVersions` (`plan_review.go`): each distinct non-empty text the field's changes move between, in the order the trail first shows it, then the current text if the trail never reaches it. A `versions:` block follows naming the version count and `lit history <id> --version <field>@<n>` for each such field holding a version other than its current text. `--version <field>@<n>` prints version n's text bare. A malformed reference is a usage error, checked before the id is read; a version past the recorded ones is `storage.VersionNotFoundError`, exit 4, reason `version_not_found`. Each plan review (`detail.PlanReviews`) is a row of the same trail, `- [<reviewer> @ <local timestamp>] verdict <pass|fail> on plan v<n> — laws: <token>, …` (`-` for none), where `v<n>` is the version whose text the review's `plan_digest` hashes to, or `of a text its history does not hold (<digest>)` in its place when no recorded version does (`planVersionLabel`, `output.go`); events and reviews are stable-sorted together by time, an event first on a tie (`printHistoryTrail`, `output.go`). No plan text is printed for a review.

**`lit show <id>`, plan section** (`printCurrentPlan`, `output.go`). An issue with a non-empty plan prints `plan (v<n>):`, the plan text, then `reviews of plan v<n>:` and per review of the current text `- <verdict> [<reviewer> @ <local timestamp>] laws: <tokens or ->`, or `reviews of plan v<n>: none — lit verdict records one` when there is none. A review is of the current text when its digest equals `model.DigestPlan` of it (`PlanReview.Judges`, `plan_review.go`), so a review of another version is not listed, and a plan edited back to a reviewed text lists that review again. An empty plan prints nothing.

**`lit verdict <id> <pass|fail> --version <n> [--law <token>]...`** (`verdict.go`). Two positionals and a `--version` of at least 1, else usage error `usage: lit verdict <id> <pass|fail> --version <n> [--law <token>]...`, exit 2. The verdict parses through `model.ParsePlanVerdict` (`pass`, `fail`; anything else `verdict must be pass or fail, got "<raw>"`, exit 3); each `--law` (repeatable, never comma-split) through `model.ParseLaw`, which admits `^[a-z][a-z0-9]*(-[a-z0-9]+)*$` and refuses anything else with `a law is its token, lower-case words joined by hyphens (one-source-of-truth), got "<raw>"`, exit 3. The reviewer is the acting identity (`registerActor`). `Store.AddPlanReview` reads the issue and its events and calls `storage.PlanReviewOf` (`internal/storage/plan_review.go`), pure: version n of `plan` per `storage.TextVersions`, or `storage.VersionNotFoundError` (exit 4, `version_not_found`); the laws sorted and deduplicated (`model.CanonicalLaws`); a `fail` with no law refused with `a failing verdict cites at least one law the plan breaks` (exit 3); a blank reviewer recorded as `unknown`. An id naming no issue is `storage.NotFoundError`, exit 4. The engine stamps id `rvw-<uuid>` and its clock's time and inserts one `plan_reviews` row. Prints `<issue-id> <review-id>: <verdict> on plan v<n> — laws: <tokens or ->`. Event facts `verdict.value`, `verdict.plan_version`, `verdict.laws` (the cited count).

**`lit children <parent-id>`** (`cli.go`, `register.go`): the `ls` leaf under a second name. `runList` builds both commands from one `listLeaf`; the `children` surface takes one positional, which is appended to the `--parent` ids, so `lit children <id> [flags]` prints what `lit ls --parent <id> [flags]` prints and accepts every `ls` flag, including `--at`. The `ls` defaults therefore apply: the active-work status filter hides closed children, archived and deleted children are hidden without `--include-archived`/`--include-deleted`, and the columns are `id,state,topic,title`. Any positional count other than one, or a blank id, → usage error `usage: lit children <parent-id> [flags]  (got N positional arguments: [...])`, raised after the parse and before any store opens; flags may come before or after the id, including boolean flags and `--`; a parent id naming no issue → exit 4.

**`lit orphaned [--assignee <u>]...`** (`cli.go`; `--assignee` is the same set as on `lit ls`): `in_progress` leaves untouched ≥ 6h, oldest first; rows are `id | state | topic | assignee | title | Last Update: <age>`; empty prints "No orphaned issues."

## `lit backlog` and `lit next`

**`lit backlog`** (read; `workable.go`, `backlog.go`). Flags: `--assignee`, `--type`, `--status` (`open`|`in_progress` only — `closed` is refused, exit 3), `--labels`, `--limit` (applied after ordering; negative exit 3), `--columns`. `--assignee`, `--type` and `--labels` are the sets `lit ls` takes, parsed by the same functions, so a bad member exits 3 as there (`workableFilterFlags.parse`, `workable.go`). Any positional → usage error. Output: an eight-line fixed preamble explaining the ranked queue, an 80-char rule, then either `(backlog empty)` or numbered rows (`%2d. <columns>`) each followed by an indented context block: `epic:`, `blocked:` (non-dependency reasons only — `missing <field>`, `needs-design`, `external`, `earlier sibling <id> still open`), `blocked by:`, `in_progress: <age>[ (ORPHANED)]` — the suffix withdrawn when somebody holds the row's lane, since the claim line beneath names them — the claim line when the row's lane is held, and `unblocks:` (derived from the listed rows only). If any row has a rank inversion, a trailing warning tells the user to run `lit doctor --fix`. Claims here are visibility only — they block nothing.

**`lit next`** (read; `next.go`, `next_route.go`). Flags: `--assignee`, `--type`, `--status` (`open`|`in_progress`), `--labels`, and `--all` ("Ignore the focus scope and route over the whole queue") — no `--limit`, no `--columns` (`next.go`) — plus the `--by` identity fallback (`next.go`), which `next` alone among read commands registers. The retired `--continue` is refused with an `UnsupportedError` (`flagset.go`). The command is registered `app.AccessRead` (`register.go`) and performs no writes.

Admission is one predicate, `capacityFor` (`next_route.go`), which classifies a row into one of three capacities against the lane's standing and this checkout's identity; the capacities and the per-case mapping are in `08-claims-and-identity.md`. A lane whose claim has expired is unclaimed — a legitimate bare-`next` target for every checkout, the one that let it expire included, with nothing said about the old claim — and a lane another checkout holds is routed around. A locked worktree keeps its lane held past the clock (the derivation folds the lock into `Held`), so another checkout's locked worktree is routed around however far its clock has run, and this checkout's own is resumed (`claims_takeover.go`). There is no `status == open` gate on servability, so an in-progress row in a lane this checkout holds is handed back to be resumed rather than hidden, and one in a lane nobody holds is offered as abandoned work.

`routeNext` (`next_route.go`) is the precedence, over the lanes and epics `ownScope` (`next_route.go`) derives from the standings. A checkout holding at least one lane runs steps 1–3. Step 1 takes the first-ranked row of its own lanes, accepting `{serveWork, resumeWork}` — `ResumedOwnWork` or `ServedFromClaim`. Step 1b takes the work toward an on-path dependency outside our lanes that gates one of them — the dependency itself, or a ticket under it when it is an epic (`onPathDependency`, `next_route.go`) — as `ServedFromDependency`, whose `Gates` names the blocked row the pick unblocks and `Blocker` the dependency. Step 2 takes the rest of our epic, in lanes we do not already hold, accepting `serveWork`, as `ServedFromEpicLane`. Step 2b runs `onPathDependency` again over our lanes and our whole epic, as `ServedFromDependency`. Every step serves only rows the run's filter (`asked`, a `storage.IssueCriteria`) selects, while every walk reads the whole workable queue. When they find nothing but the same steps over the whole queue would serve a row, step 3 is `Narrowed`, whose `Hidden` is that row — carried with the pool's pick as `ServedPastNarrowing`, and returned alone only when the pool has no pick. Otherwise step 3 builds `Exhausted` and hands it, with the focus-scoped global pool's pick, to `ServedPastExhaustion`; only when the pool has no pick the filter selects is `Exhausted` itself the answer, carrying as `Narrowing` the pool's pick over the whole queue when there is one. A checkout holding no lanes starts at step 4, the focus-scoped global pool, yielding `ServedFromNewLane`, else `Narrowed` when the pool over the whole queue has a pick, else `NoWork`.

`NextOutcome` is a sealed sum (`isNextOutcome()`) of exactly those ten cases. `Exhausted`, `Narrowed` and `NoWork` are themselves `error` implementations and travel outward as themselves rather than being rendered into a generic error, so the exit-code and reason sinks read the routing verdict instead of a copy. All three exit 6 (`ExitNoWork`, `exit.go`) with reasons `scope_exhausted`, `scope_narrowed` and `no_ready_work` (`error_output.go`); the exit-code section above carries why 6 rather than `ExitGeneric`. The `Exhausted` and `NoWork` diagnostics are built from `reachKind`, what one row is to this checkout right now (`reachTakeable`, which neither reports because steps 1b and 2b serve it, `reachHeldFresh`, `reachNotReady`, `reachOutOfView` for exhaustion alone, and `reachOffFocusPath` for the pool alone), and each clause names at most `maxNamedPerKind = 12` ids and states how many it left out; the per-kind wordings are in inventory-claims.md §9.2.

`lit next` claims nothing, so nothing it prints is in the perfect tense. Any pick that would establish a claim prints advice about running `lit start`, worded by `startAdvice` (`next.go`) on whether the row is in progress and whether `LaneID.Describe()` (`model/model.go`) gives the lane a name — a solo lane gets none, being the ticket that names it — then the default columns plus indented `epic:`, `blocked by:`, and claim lines, never `unblocks:`, since `printNextSummary` hands `printInlineDeps` a nil unblocks map (`ready_state.go`). `renderNextOutcome` (`next.go`) has an arm per case: `ServedFromClaim` announces nothing, the six other served outcomes announce, the three terminal outcomes return themselves as errors, and the unreachable `default` panics.

## Mutating fields and rank

**`lit update <id>`** (`cli.go`). Flags: `--title`, `--description`, `--prompt`, `--plan`, `--description-file`, `--prompt-file`, `--plan-file`, `--type`, `--priority`, `--assignee`, `--labels` (replaces the whole set), `--lane`, `--reason`, `--by`. Only flags actually present are applied. `--status` is intercepted with guidance to use the transition verbs (exit 2). No field flag at all → "lit update requires at least one field flag" with the usage line, exit 2 (`--reason` alone does not count). A blank `--title` or a `--type` crossing the container/leaf line → exit 3. One field-change event records all moved fields together.

**`lit rank <id> --top|--bottom|--above <id>|--below <id>`** (`cli.go`). Exactly one mode flag required — counted by presence, so `--top=false` still counts (exit 3 otherwise). **Frame substitution**: ranking a child of an epic moves the whole epic; the command reports "`<id>` is inside `<epic>`; ranked the epic `<epic>` instead, leaving its internal order unchanged", and similarly when the anchor resolves to its epic (`cli.go`).

**`lit rank set <id1> <id2> [...]`** (`cli.go`). Atomically stacks the named issues at the top in the given order (≥2 IDs required); the same frame substitution reporting applies, then "ranked N issues at top in order: …". The literal `set` after `rank` is the only subcommand-vs-ID disambiguation in the CLI, justified because real IDs always carry a prefix (`cli.go`).

## Transitions

Nine verbs — `start`, `done`, `close`, `open`, `phase`, `archive`, `unarchive`, `delete`, `restore` — share one handler (`cli.go`). All take one issue ID (wrong arity → `UsageError`, exit 2), `--reason`, and `--by`, which `start` also writes as the assignee. Extra flags per verb: `start` adds `--take`; `close` adds `--resolution` and `--of`; `phase` requires `--to <plan|impl|review|merge>`, parsed by `model.ParsePhase` (an unknown or missing phase → `UsageError`, exit 2). The other six accept no extra flags, so e.g. `lit done --resolution x` is an unknown-flag usage error.

Sequence: build the action from the verb's flags (a bad flag value → `UsageError`, exit 2, whatever the ID names) → read the issue (missing → exit 4) → authorization (only `start` gates — the takeover gate below; `phase` reads the issue's history for the phase it leaves) → apply the change → dispatch the workflow occasion (status verbs only) → for `start`, print "claim transferred: `<old>` -> `<new>`" when somebody held the lane and the ticket's recorded claimant changed hands, and for `phase` print `phase: <from> → <to>` or `phase: <to> (unchanged)` → print the summary line → for `done`/`close`, print the **close adjacency block** (parent, in-play siblings, redirect target, related, and `unblocks:` — the still-live dependents) → breadcrumb.

**Close outcomes** (`cli.go`, shared with `bulk close`): `--resolution` is required (`duplicate|superseded|obsolete|wontfix`). `duplicate`/`superseded` require `--of <canonical-id>` ("closing as `<res>` redirects to a canonical ticket — name it with --of"); `--of` on a terminal resolution is refused. Store-side, the redirect target must exist, must not be the issue itself, and must not be deleted.

**Store refusals on every transition**: an archived or deleted issue rejects any status action with `model.FrozenIssueError` ("issue <id> is <archived|deleted>, so its status cannot change: run `lit <unarchive|restore> <id>` first"), raised by `Issue.Apply` after the container check; an epic rejects any status action with the container error (chapter 01); `archive`/`unarchive` on a deleted issue are refused. **There is no from-state precondition**: `Store.Apply` checks no prior status, and a same-state transition is a silent no-op that records nothing and preserves an existing resolution (`store.go`, `status_states.go`).

**Phase moves** (`internal/model/phase.go`). `phase` moves an in-progress leaf's phase; the status stays `in_progress`. The phase is derived, not stored: `model.PhaseOf` takes the newest event, by `model.CompareEventRecency`, among the status moves into `in_progress` (each sets `plan`) and the `phase` events (each sets its change row's `to`), and reads `plan` when none sets one. `Issue.PlanPhase` refuses an epic and a leaf that is not `in_progress`, then an archived or deleted issue, each a `model.ValidationError` (exit 3); a move to the current phase is a no-op that records nothing. A move records one event with action `phase` and a `phase` change row, and sets `updated_at` under a guard that the row is still `in_progress`. The command's event records `phase.from`, `phase.to` and `phase.changed`.

**The `start` takeover gate** (`claims_takeover.go`). Before applying, `start` asks `Issue.Apply` whether the start can land, so a frozen issue or a container is refused before any lane is gated; then it derives the issue's lane and the current claim standing: held by self, or unclaimed → proceed silently, and a lane whose claim has expired is unclaimed, so a start on it prints nothing about the claim that used to be there (a locked worktree keeps its lane held past the clock, so a lock is gated as the live hold it is — silent when it is this checkout's own, fresh-confirm otherwise); **held by another** → `--take` proceeds at a terminal or not; without it, non-interactive callers get "this lane is claimed and active; pass --take to confirm the takeover" (exit 3); an interactive terminal is asked `take over this lane?` with a ` [y/N] ` suffix (anything not starting with `y` → "takeover declined", exit 3). Both refusals carry the `takeover_unconfirmed` remediation, which names `--take` and `lit next` rather than a retry, and tells agents to pass `--take` only when the user directs the takeover (`relationOf` at `claims_takeover.go`, `authorizeStart` at, `confirmFreshTakeover` at). The claim line format: `claimed here: <worktree-path> (<branch>)` when the holder resolves to a live local worktree, else `claimed: <name> (elsewhere|unaddressed)` — `<name>` is the stream's 8-char token, or `the public checkout` when the establishing event carried no attribution, and `unaddressed` is that public checkout's state, since it has no address to compare against — plus optional contested-by streams, age, and lane progress (`claims_render.go`). If local-checkout enumeration fails, a warning is printed and freshness alone governs.

**`lit purge <id> [--yes]`** (write; help group Issue Retention, summary "Permanently remove an issue and everything it owns"; `purge.go`, `register.go`, description `helptext/purge.txt`). Not a transition verb and not a retention state: it removes the issue for good through `Store.Purge` (chapter 03). Flags: `--yes` (bool, default false) and `--by`, which supplies the purge record's actor. A positional count other than one → usage error, `usage: lit purge <id> [--yes]` (exit 2). Sequence: read the issue (missing → exit 4, reason `entity_not_found`, before any confirmation is asked for) → confirmation gate → purge → print `purged <id> (comments=<n> labels=<n> edges=<n> events=<n> plan_reviews=<n>)`, the numbers of the issue's comments, labels, relations at either end, history events, and plan reviews removed with it. The title is not printed. The gate (`confirmPurge`): `--yes` proceeds, at a terminal or not; without it, a non-terminal stdout refuses with "purging <id> cannot be undone; pass --yes to confirm it" (exit 3); a terminal is shown the id and "a purge removes it, its comments, labels, history and edges for good, here and in every store it syncs to", never the title, then asked `purge it?` with a ` [y/N] ` suffix, and an answer whose trimmed lowercase form does not start with `y` → "purge declined" (exit 3). Both refusals are `purgeUnconfirmedError`, reason `purge_unconfirmed`, whose remediation is "Rerun with `--yes` to purge it, or run `lit delete <id>` to remove it reversibly." plus an `<agent-instructions>` envelope saying a purge cannot be undone, reaches every store lit syncs with, and takes `--yes` only when the user directs it (`error_output.go`). An issue whose purge would leave a child leaf with no parent edge, deleted and archived ones included, is refused by the store (exit 3, `validation_refused`), naming those children; a child epic is left top-level and does not refuse it. The terminal prompt and the takeover prompt share one reader, `askYesNo` (`claims_takeover.go`).

## Relations, comments, labels

**`lit dep add <id> --blocked-by <blocker-id> | --related-to <peer-id>`** (`dependency.go`). One positional and exactly one relation flag; the positional is the edge's src and the flag's value its dst, the stored order (chapter 01), so `lit dep add A --blocked-by B` records "A blocked-by B". `parent-child` is not writable here — `lit parent set` owns it. Refusals in order: a positional count other than one, or other than exactly one relation flag → usage (exit 2); self-loop → validation error (exit 3); then the store's `AddRelation` (chapter 03): an edge already present (a `related-to` named either way round) → exit 6, `state_already_holds`: nothing to add, answered before any rule below judges it; for `blocked-by` only, both endpoints leaves directly under one epic, or an endpoint inside the other's epic at any depth (climbing only through epic parents) → validation error (exit 3): "Do not set blocked-by relationships between two issues in the same epic.  Use rank…" (two floating issues never trip this); an edge that would close a transitive cycle → exit 3. Output line: the edge as a sentence in stored order, `<src> blocked by <dst>` or `<src> related to <dst>`.

**`lit dep rm`** — same shape, no self-loop or same-epic check; prints `ok`. **`lit dep ls <id> [--type blocked-by|parent-child|related-to]`** — one line per relation, the same sentence in stored order (`<child> child of <parent>` for parent-child); empty output for none.

**`lit parent set --child <id> --parent <id>`** / **`lit parent clear <child-id>`** (`issue_relations.go`): `set` prints the edge as `<child> child of <parent>`, answers a `--parent` that is already the child's only parent with exit 6, `state_already_holds`, and refuses a `--parent` that is not an epic (exit 3); `clear` prints `ok` for an epic, which it lifts to the top level, and refuses a leaf (exit 3, "cannot detach X from its epic: a task lives inside an epic, so move it with lit parent set --child X --parent <epic-id>").

**`lit comment add <id> (--body <text> | --body-file <path|->)`**: blank body → "comment body is required" (exit 3); comment IDs are `cmt-<uuid>`; prints `<issueID> <commentID>`; no breadcrumb. **`lit comment rm <comment-id>`**: blank ID → "comment id is required" (exit 3); unknown ID → exit 4; prints the deleted pair (`cli.go`).

Every long free-text flag — `--body`, `--description`, `--prompt`, `--plan` — has a `--<name>-file <path>` twin that reads the text from a file, or from stdin when the path is `-`; giving both forms of one field is a usage error (exit 2), and so are a path that cannot be read, a file or stdin whose text is blank ("--<name>-file <path> supplied no text"), and two fields of one invocation both naming stdin ("only one field can read stdin, and --description-file and --prompt-file each name it; give the others a path"). The text is read in the parse, before the workspace opens, so these refusals need no workspace and a slow pipe holds no lock. The event records each field's `text_source.<name>` as `absent`, `inline`, `file` or `stdin` (`longtext.go`).

**`lit label add|rm <issue-id> <label>`**: normalizes through the label rules (chapter 01), prints the resulting full label set comma-joined. Reserved labels: `needs-design` and `external` block readiness; `focus` marks a focus-path goal (`issue_relations.go`).

## Bulk operations

`lit bulk <label|close|archive>` (`bulk.go`). `--ids` is a set on all three, comma-separated and/or repeated (`registerBulkIDs`). Shared semantics: the operation applies to each ID **in order**; each success prints `<id> ok` to stdout; failures never reach stdout — they are collected into a partial-failure error (exit 1) whose message lists every `<id>: <err>`, with remediation "Re-run the command for only the failed IDs…".

- `bulk label <add|rm> --ids <csv> --label <name>` — refusal precedence: missing `--ids` or a blank slot in it (exit 3), then missing `--label` (exit 3), then unknown action.
- `bulk close --ids <csv> --resolution <res> [--of <id>] [--reason <t>]` — same outcome gate as `lit close`; one shared outcome/actor/reason applied to every ID. No workflow events, no adjacency block, no breadcrumb.
- `bulk archive --ids <csv> [--reason <t>]`.
- `bulk import` is retired (hidden): points to `lit backup restore --path <export.json>`, exit 3, and answers even outside a git repository.

## Import and export

**`lit export`** (read): writes the full store export as two-space-indented JSON to stdout — the interchange shape of chapter 01 (`cli.go`).

**`lit import --path <file>`** (write; `cli.go`). Format chosen by extension: `.yaml`/`.yml` → bulk create-or-update, anything else → JSON tree spec.

- *JSON tree*: an array of records with `local_id`, optional `parent` (a local_id), optional `blocked_by` (local_ids), `title`, `type`, `topic`, `priority`. `--by` is refused here — tree imports always attribute creates to `links`. Output: `imported N issues` then `  <local> -> <real>` mappings (map order unspecified). Rollback on failure is best-effort; the doc comment tells callers to run `lit doctor` after a failed import.
- *YAML bulk*: one document per issue, `---`-separated; optional `local_id` for intra-file references; a document with `id` set **updates** that issue instead of creating; `parent` may name a local_id or a real ID. `--by` requires at least one update document. Output: `created N issues` with mappings, then `updated N issues` with IDs.

## Workspace metadata and shell support

**`lit prefix set <new-prefix> [--apply]`** (workspace-mode; opens the store read-only itself, and runs before one exists; `prefix.go`). Without `--apply`, prints a preview; with it, writes `issue_prefix` to the workspace `config.json`. Every outcome also prints `issue ids in this store use: <census>` — the prefixes the existing ids carry, with counts — so an operator can tell repairing `config.json` back to the backlog's prefix from rewriting it to a new one. Before the store exists the census reads `none (no store yet)`. Existing issue IDs keep their old prefix; only new issues use the new one. An unchanged normalized prefix prints "(prefix unchanged)". It runs in a workspace whose stored prefix the rules refuse, and is the repair the `stored_prefix_refused` remediation names. Any invocation not starting with the literal `set` → usage error.

**`lit workspace`**: prints `workspace_id`, `issue_prefix`, `git_common_dir`, `storage_dir`, `database_path`, `dolt_repo_path`, `traces_dir` as `key: value` lines (`cli.go`).

**`lit completion <bash|zsh|fish>`** (`completion.go`): generates a completion script from the visible command tree (hidden and retired commands never appear; a synthetic `help` entry is added). Family trigger words are flattened across depths, unioning children when a word appears under two parents (e.g. `label` both top-level and under `bulk`). Wrong arity or unknown shell → usage as plain error, exit 1.

**Bare `lit` / `lit quickstart`** — the guidance printer; flags `--refresh`, `--eject[=LIST]`, `--force`, one optional topic. Refusals: more than one topic; `--refresh` with `--eject`; `--force` without `--eject`; a topic combined with any flag; an unknown topic (all exit 2). Full behavior in chapter 07.

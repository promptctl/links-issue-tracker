Workflows are user-authored guidance lit injects into its own output at
declared moments in the work lifecycle. One definition is a markdown file
with YAML frontmatter: the frontmatter says when to fire, the body says what
to inject. Nothing here is enforced — a definition only adds text to what a
command already prints; it never blocks or gates anything.

Where definitions live

  A definition is any *.md file found recursively under a layer root. Three
  layers, nearest first:

    project    .lit/workflows/ in this repository (checked in, team-wide)
    global     workflows/ under lit's config directory —
               $XDG_CONFIG_HOME/links-issue-tracker/ when that is set,
               otherwise ~/.config/links-issue-tracker/
    embedded   defaults shipped inside the lit binary

  The folder hierarchy under a root is arbitrary; the path carries no
  activation meaning, only frontmatter decides when a definition fires.
  Definitions resolve by id with the nearest layer winning outright: a
  project file with the same id as a global or embedded one replaces it
  whole, never field by field. An id defaults to the file's layer-relative
  path with .md dropped and spaces turned to underscores, so the same
  relative path at two layers overrides without declaring an id at all.
  Within one layer a duplicate id keeps the first file in lexical order and
  warns about the rest. Loading never fails a lit command: an unreadable or
  malformed file never fires and becomes a warning instead. It still holds
  its id, so a farther layer's definition of that id does not fire in its
  place.

Format

  A minimal, legal definition:

    ---
    id: done
    name: Post-close capture reminder
    when: [enter closed]
    labels: [user-facing]
    ---
    Ticket <id> is closed. Capture what the next agent needs to know
    before moving on.

  lit reads four keys: id, name, when and labels, each optional. A file
  carrying any other key never fires, with a warning naming the key: lit
  cannot tell whether a key it does not read was meant to narrow when the
  definition fires, so it does not guess. Such a file still holds its id,
  so a farther layer's definition of that id does not fire in its place. In
  the body, <id> is replaced with the acted-on ticket's id when the moment
  has one.

Activation

  when     The moments the definition fires at. Each entry is one of:

             enter <state>   the ticket's state changes into <state>
             exit <state>    the ticket's state changes out of <state>
             <event>         lit shows or records something (see below)

           The built-in states are open, in_progress and closed, and the
           phases plan, impl, review and merge inside in_progress (see lit
           phase). A state inside another moves with it: lit start from
           open exits open and enters in_progress and plan, lit done exits
           the ticket's phase along with in_progress and enters closed, and
           lit phase exits one phase and enters another without leaving
           in_progress. A crossing fires whichever command makes it, single
           or bulk: lit done and lit close both enter closed, and lit open
           exits closed and enters open. A call that leaves the ticket's
           state where it was — a move to the phase it is in, an archive or
           delete or their undoing — crosses nothing, so only a definition
           bound by labels alone fires on it.

           An entry naming no state above and no event below — a typo, a
           blank, an event another lit fires — never fires, and is reported
           as a warning.

  labels   The acted-on ticket carries any listed label. Labels are
           lowercased on both sides, so case never matters. A label that no
           ticket could carry (a blank, or one containing a comma) is
           dropped with a warning rather than silently never matching.

  The entries of one key are alternatives (OR). A definition declaring both
  keys fires only when both hold (AND): when: [enter closed] plus
  labels: [user-facing] fires as a ticket carrying user-facing closes. A key
  left out constrains nothing, but a key declared with no entry lit can read
  never holds, so the definition never fires rather than firing on the
  other key alone. A definition declaring neither key never fires either: it
  loads and holds its id, and lit workflows flags it under Warnings.

Events

  The moments lit fires that are not a change of state, and what fires each
  one today:

    show_backlog       lit backlog
    next_pulled        lit next, when it has a ticket to hand back
    show_ticket        lit show
    ticket_created     lit new, lit followup
    ticket_updated     lit update
    comment_added      lit comment add, lit bulk comment

The subcommands

  Bare lit workflows prints every moment a when: entry can name, spelled as
  one — each event, then entering and exiting each built-in state, the
  phases after in_progress — and every label a loaded definition binds to,
  annotated with the definitions active at each and the layer each resolved
  from. A Warnings section follows, naming every file that loaded but cannot
  fully fire: no keys, an entry naming nothing lit fires, a key lit does not
  read, malformed frontmatter, duplicate id. Every command that fires a
  moment prints the same warnings on stderr, one line each, once per
  command.

  show <id> prints one resolved definition: id, name, source layer, path,
  its when and labels entries, the warnings for its file, and its body.

  edit <id-or-point> scaffolds a project-layer file and prints its path. It
  resolves the argument two ways:

    An existing definition's id — override it. A project-layer definition
    already is the override, so edit just opens it; a global or embedded
    one is copied verbatim into .lit/workflows/ at the same relative path,
    ready to change.

    Anything else is a point with nothing bound there yet: a when: entry
    lit fires (enter <state>, exit <state>, or an event above) is scaffolded
    under when:, anything else a ticket could carry as a label, and a point
    that is neither (a blank, or one containing a comma) is refused. The
    fresh file shows the other key as a comment and the requested one live,
    and edit prints the line it bound, so a point meant as a moment but read
    as a label shows as one.

  edit never overwrites — an occupied path fails with a conflict message,
  so edit that file directly or pick another point. It always prints the
  path, and additionally opens $EDITOR only when stdout is a terminal and
  $EDITOR is set; an agent, a pipe or a script gets the path alone.

  The guidance printed after lit done and lit close is the embedded
  definition with id done, bound to when: [enter closed]. Run lit workflows
  edit done to copy it into .lit/workflows/done.md and rewrite the body; add
  a labels key there to narrow it to matching tickets, since the two keys
  then AND together. Delete that file to fall back to the embedded default.

  dry-run answers "what would inject here" without a real occasion. The
  flags describe a hypothetical one; the output names every definition that
  would fire, which when entry or label matched it, and the body that would
  be injected, with <id> interpolated from --issue. --when takes an entry
  spelled as in a definition and repeats, since one transition makes several
  crossings (--when "exit open" --when "enter in_progress" --when "enter
  plan" is a start); --label repeats too. A key left unset satisfies no
  definition that declares it. A --when naming no moment lit fires, blank
  included, is refused, as is a --label no ticket could carry; a --label is
  lowercased as a ticket's is. A hypothetical matching nothing exits cleanly
  with Fired (0). dry-run writes nothing and reads no ticket data.

  A real occasion that fires at least one definition records a JSON trace —
  the occasion, every definition that fired, and the same reasons dry-run
  prints — under traces/workflows/ in the workspace storage directory that
  lit workspace reports as storage_dir. An occasion matching nothing leaves
  no trace.
